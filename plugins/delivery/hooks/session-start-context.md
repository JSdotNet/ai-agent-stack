Route these task categories through the matching flow-* skill: architecture, ADR, arc42, blueprint, TDR -> flow-architecture, flow-adr, flow-arc42, flow-blueprint, flow-tdr; feature work -> flow-feature; bug fixes -> flow-bug; existing repository structure or layout refactors, folder moves, project/solution organization fixes, or test/harness placement changes -> flow-structure; new module or service -> flow-create-module, flow-create-service; dependency or package updates -> flow-update-packages; Aspire upgrades -> flow-aspire-update; MVP creation -> flow-create-mvp; repository or project scaffolding -> flow-repo, flow-project; any other task category no flow-* skill covers, such as tooling, CI, scripting, or housekeeping -> flow-fallback. This list is the plugin-provided baseline, not an exhaustive catalog: a repository may provide additional repo-native flow-* skills in the host's own skill folder, and those take precedence for the task categories they cover. flow-fallback is the last resort, not an escape hatch: use it only when no skill covers the category or when the matched skill targets fundamentally different work, never because a matching skill's preconditions are unmet. If you decide not to use a flow skill for one of these categories, say so explicitly and give the reason before continuing. A flow is one session: fan-out across sessions and worktrees belongs to the fleet plugin, never to a flow. Every flow reports progress through whichever delivery surface is bound, resolved by pattern from the live tool list rather than by a hardcoded tool prefix, and no surface bound is a normal outcome that never blocks a stage. A repository declares its bindings, extensions, policy, and gates in .github/ai-agent-stack.json; configuration chooses among behaviour the engine already implements and never adds a stage. Configuration may add human gates anywhere; it may never remove the Personal Validation gate or hand a gate to a plugin. Model choice is personal and never comes from the repository: it is resolved from the model-override host slot, and .github/ai-agent-stack.json carries no model key. A repository may declare runtime and QA context in .claude/flow-context.md. The repository's own MCP configuration and instruction files remain the source of truth for MCP servers.
