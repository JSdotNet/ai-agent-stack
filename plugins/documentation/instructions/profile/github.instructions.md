# GitHub Profile Instructions

## Purpose

- Apply these rules when editing any file under `**/profiles/github/*.md`.
- Audience: collaborators, recruiters, maintainers, and developers visiting a public GitHub profile.
- Focus on clear positioning, technical credibility, and easy next actions for the reader.

## Scope

- This folder is for **GitHub profile** content only.
- Typical examples: profile README drafts, public profile summaries, and profile highlight pages.

## Recommended Structure

1. `# Title` - name, handle, or positioning line.
2. `## Overview` - short hook explaining what you build and for whom.
3. `## Focus Areas` - technologies, domains, or problem spaces.
4. `## Highlights` - selected achievements with links or proof.
5. `## Selected Projects` - 1-3 projects with one-line value statements.
6. `## Collaboration` - how people can follow up, collaborate, or explore more.

## Writing Rules

- Lead with current value and direction, not full biography.
- Keep paragraphs short and scannable; prefer bullets for highlights.
- Link to repositories, talks, demos, or articles when available.
- Use metrics, outcomes, or lessons where they strengthen credibility.
- Use emojis sparingly and only when they improve scanning.
- Mark missing proof points or links with `[TODO: ...]`.

## Safety and Accuracy

- Do not include private email addresses, phone numbers, or confidential client details unless the user explicitly wants them published.
- Avoid unverifiable claims and inflated superlatives.
- Prefer public proof over unsupported statements.

## Final Checklist

- [ ] Hook is clear and public-facing.
- [ ] Focus areas and highlights are specific.
- [ ] At least one proof link or TODO placeholder is present.
- [ ] Collaboration path or CTA is present.
- [ ] No sensitive information is included.
