# GitHub Project Profile Instructions

## Purpose

- Apply these rules when editing any file under `**/profiles/github/projects/*.md`.
- Audience: developers, maintainers, reviewers, and potential users evaluating a project.
- Focus on what the project solves, who it helps, and why it is worth exploring.

## Scope

- This folder is for **GitHub project profile** content only.
- Typical examples: project showcase pages, repository profile summaries, and portfolio-ready project snapshots.

## Recommended Structure

1. `# Project Name`
2. `## Summary` - one short paragraph describing audience, problem, and differentiator.
3. `## Problem and Audience`
4. `## Solution and Notable Choices`
5. `## Impact or Proof`
6. `## Links` - repository, demo, article, or talk.
7. `## Next Step` - invite the reader to try, review, or discuss the project.

## Writing Rules

- Start from user value before implementation details.
- Keep technical depth selective; highlight only choices that help readers understand the project.
- Prefer concrete outcomes, lessons, or constraints over generic feature lists.
- Use short bullets for proof, architecture highlights, or related links.
- Use `[TODO: ...]` for missing metrics, screenshots, or URLs.

## Safety and Accuracy

- Do not expose credentials, internal endpoints, or private roadmap details.
- Do not overstate project maturity; be explicit when something is experimental.
- Keep external wording understandable without internal company context.

## Final Checklist

- [ ] Problem and audience are explicit.
- [ ] Solution summary is concise and differentiated.
- [ ] Proof, links, or TODO placeholders are present.
- [ ] Next step or CTA is present.
- [ ] No confidential implementation details are included.
