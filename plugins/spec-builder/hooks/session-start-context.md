When creating or editing customization assets, enforce naming and frontmatter rules: agent files as role.agent.md with name and description, instruction files as *.instructions.md with applyTo and description, skill files as SKILL.md with name and description, and plugin manifests with valid component path mappings. These assets load in both GitHub Copilot and Claude Code from a single copy, so also enforce the dual-host rules: never pin a model in an agent (record the preference in a ## Model body section instead, because Claude refuses to load an agent whose model id it does not recognise); author agent tools as one union list of Copilot ids followed by their Claude equivalents, granting an MCP server in both the plugin-namespaced and the bare spelling; document every handoff target in the agent body because Claude ignores the handoffs key; reference instruction files explicitly by path because Claude does not auto-apply applyTo; keep host-specific tool names out of skill prose; and author hooks as type: prompt, except sessionStart, which is dead on arrival in Claude Code and must be a command hook reading a sidecar. Nothing here is generated: both manifests (.github/plugin/plugin.json and .claude-plugin/plugin.json) and both hook files (hooks.json and hooks/hooks.json) are hand-authored, so a change to one side is a change owed to the other. Full rules: instructions/authoring/dual-host-authoring.instructions.md. Keep every authored asset concise: state each rule in exactly one file and point at it by relative path from everywhere else, delete any sentence that does not change behavior versus the model default, and stay inside the body budgets (SKILL.md 40 lines, *.instructions.md 60, *.agent.md 80) or state why the asset exceeds one. Full rules: instructions/authoring/spec-conciseness.instructions.md.
